# 파트별 팀 관리

## 사용 방법
과제 관리 아래의 **파트 관리**에서 **파트 사용**을 켠 뒤 파트를 추가합니다.
사용 가이드 위의 **파트 선택**에서 관리할 파트를 선택하면 팀 현황, 과제 현황,
주간 보고 작성, 주간 보고 라운지, 멤버 관리, 과제 관리가 선택한 파트로 전환됩니다.

기존 데이터는 **미지정 · 기존 데이터**에 유지됩니다. 이 기능은 기존 멤버나 과제를
자동 배정하지 않습니다. 선택한 파트에서 새로 등록한 데이터는 그 파트에 저장됩니다.
파트 선택은 브라우저에 팀별로 저장됩니다.

파트 사용을 끄면 기존 파트와 소속 정보를 삭제하지 않고 팀 전체를 표시합니다.
다시 켜면 기존 파트를 그대로 사용할 수 있습니다. 빈 파트는 삭제할 수 있지만
멤버·과제·일정·보고가 있는 파트는 삭제할 수 없습니다.

## 데이터 구조
- `teams.parts_enabled`: 파트 사용 여부. 기존 팀은 기본값 0.
- `parts`: 팀별 파트 이름과 파트별 보고 자동 개설 설정.
- `users.part_id`, `project.part_id`, `team_events.part_id`, `reports.part_id`:
  소속 파트 외래 키. 미지정 또는 기존 파트 미사용 데이터는 SQL `NULL`.
- 마일스톤·워크는 과제, 보고 항목은 보고 주간의 파트를 따릅니다.
- 파트를 켜도 기존 행을 임의 배정하거나 기존 보고 내용을 변경하지 않습니다.

## API 범위
클라이언트는 선택한 팀과 파트를 `X-Wia-Team`, `X-Wia-Part` 헤더로 전송합니다.
파트를 사용 중인데 파트 헤더가 비어 있으면 미지정 범위입니다.
파트 사용이 꺼져 있으면 빈 파트 헤더로 팀 전체를 조회합니다.
파트 구분은 데이터 관리 범위이며 기존 로그인 체계를 대체하는 인증 수단은 아닙니다.

파트별 멤버, 과제, 일정, 보고 목록을 구분하고 직접 ID로 조회·변경하는 요청도
상위 과제 또는 보고의 소속 범위를 확인합니다. 다른 파트의 멤버를 새 과제나
일정에 배정할 수 없습니다. 파트 사용을 끈 동안 작성한 보고의 원래 참여자와 내용은
다시 켠 뒤에도 해당 보고에서 유지됩니다.

파트별 자동 보고 개설은 기본적으로 꺼져 있습니다. 각 파트의 주간 보고 작성 화면에서
일정 설정을 켤 수 있습니다. 미지정 범위는 기존 팀의 자동 개설 설정을 사용합니다.
