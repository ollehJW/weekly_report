# 계정 비밀번호 생성·설정·초기화

- 신규/초기화 계정에는 업무 정책에서 지정한 공통 초기 비밀번호를 유지한다. 기존 계정의 비밀번호는 배포로 변경하지 않는다.
- 초기 비밀번호는 24시간 후 만료되며 최초 팀 로그인과 멤버 보고 작성 시 12자 이상의 새 비밀번호로 변경해야 한다.
- 팀 생성·초기화는 관리자만, 멤버 생성·설정·초기화는 해당 팀의 유효한 세션 또는 관리자만 수행할 수 있다. 초기화는 기존 비밀번호를 무효화하고 팀 로그인 세션을 종료한다.
- 생성·초기화 API는 비밀번호 값을 응답하지 않는다. 기존 프론트엔드가 사용하지 않던 temporary_password 필드를 제거했다. 외부 연동이 이 필드를 사용했다면 연동 수정이 필요하다.
- 공통 초기 비밀번호는 프론트엔드 배포 코드와 안내/확인창에 넣지 않는다. 관리자가 별도로 전달한다.
- 로그인, 변경, 멤버 설정 및 보고 인증은 native password input에 값을 보관하고 제출 때 FormData로 읽는다. React 상태/렌더링 props에 비밀번호를 전파하지 않는다. 오류 후 재입력, Enter 제출, 초기 변경 팝업의 현재 비밀번호 채움과 초기화 후 입력 비우기를 유지한다.
- 보고 삭제는 UUID 형식과 workspace 경계 및 심볼릭 링크를 검사한 뒤 DB와 파일을 삭제한다.

## 남는 위험

공통 초기 비밀번호를 유지하므로 미변경 계정에 대한 선점 위험이 남는다. 화면에서 숨겼다는 이유로 공통 비밀번호 정책 자체가 안전해지는 것은 아니다. HTTP 접속에서는 로그인/변경 요청과 세션 토큰이 암호화되지 않으므로 배포 환경의 HTTPS 강제도 필요하다. 이번 변경은 URL·인증서·프록시 정책을 변경하지 않는다.

## 검증

`python -m unittest discover -s tests -v`, `npm run build` 및 `tests/credential_browser.cjs`를 임시 DB·별도 포트에서 수행한다. 기존 운영 DB에서 테스트 계정을 생성하지 않는다.
